# 炼金技能 3–8：实现与验收

目标版本：Minecraft Java 26.1.2。`pack.mcmeta` 与配套资源包版本范围按本机游戏的 `version.json` 分别设置为 101.1 / 84.0。

## 技能与入口

| 技能 | 入口 | 当前行为 |
| --- | --- | --- |
| 3 殿堂秘药 | F，`pot.swap` | 消耗一次奥术瓶魔力；魔法伤害提高 `10+3X` / `10+5X` %，速度 +15%，持续 120 / 160 tick；冷却 100 tick，经 aptitude 修正 |
| 4 天使花园 | 潜行 F，`pot.sswap` | 持续 400 tick，每 100 / 60 tick 补充伤害吸收 I；二级成功施放主动技能时补充 400 tick 伤害吸收 II；冷却 600 tick，经 aptitude 修正 |
| 5 聚能释放 | 丢弃奥术瓶，`pot.drop` | 恢复自己丢弃的瓶子，消耗一层储能，发射速度 2.5 的无重力炸弹；伤害为投掷时瓶子主伤害的 150%，半径为 125% |
| 6 暗影潭 | 潜行投掷奥术瓶，`alch.pas2` | 首个符合条件的瓶子在投掷时占用 200 tick 冷却，落点生成 120 tick 毒潭；每 20 / 15 tick 造成投掷时瓶子主伤害的 15% / 25%，并施加缓慢 I、虚弱 I |
| 7 分析 | 地图敌人死亡回调，`alch.pas3` | 16 格内炼金师各有 100 tick 冷却，生成本等级的幸运礼物；任意非旁观且存活的玩家接近至 1.25 格内拾取 |
| 8 魔法之春 | 奥术瓶、聚能炸弹落点，`alch.pas4` | 对施法者 16 格内的目标，按负面效果种数增加魔法伤害；同时清除落点范围玩家的虚弱与易伤 |

`X` 使用物品 `ArcanePot.damage`，保留小数。秘药消耗遵守永恒毒流 II 的 20% 魔力减免。奥术瓶主伤害按投掷时魔法系数计算；炸弹不复制瓶子的附带状态与独立命中特效。毒潭的后续脉冲不再次触发魔法之春。

## 未明确数值的实现约定

- 聚能释放初始储能为 0。每三个有效敌人击杀，一 / 二级分别获得 1 / 2 储能，上限 2 / 3；达到上限时不额外囤积整组击杀。切换职业或卸下技能会清空储能。
- 炸弹飞行至多 80 tick，超时同时清理弹体与乘客，不爆炸。使用原版雪弹的方块与实体碰撞规则。
- 暗影潭立即进行首轮脉冲，之后按间隔结算，一 / 二级合计 6 / 8 轮。一次散射仅首个符合条件的瓶子携带毒潭。飞行落空也消耗本次冷却。
- 花园在第 5 / 3 秒首次给予周期护盾。未耗尽的更高等级护盾受到保护；更高等级护盾耗尽后可在周期到来时改为新的 I 级护盾。结束前最后一次获得的护盾按自身时长自然消失。
- 礼物存在 60 秒。每层提供 5% / 7% 防御值（本项目的 `luck` 属性）与魔力恢复速度，最多 3 / 5 层。混合拾取时保留已有较高等级，直到礼物层数耗尽。
- 受伤玩家每 20 tick 消耗一层礼物，调用项目既有的精确治疗接口恢复 1 生命值。该接口通过临时最大生命修饰器和瞬间治疗在实体 tick 中完成，满血时停止消耗。
- 魔力加成以整数余数累计，保留 5% / 7% 对基础每 tick 10 单位恢复的分数部分，并封顶 4000。
- “分析”接入现有地图敌人的死亡乘客回调，响应附近死亡，而不只响应自身击杀；聚能储能使用独立 `player_killed_entity` 进度并排除 `#minecraft:bypass`。

## 状态与多人归属

所有新投掷物保存 UUID、伤害、半径、魔法系数及相关技能等级。修改装备、其他玩家靠近或嵌套伤害回调不会改写已经投掷的效果。施法者离线时，炸弹/瓶子跳过伤害；既有毒潭继续施加状态并按时结束，伤害不会转交给其他玩家。

魔法之春按种类计数原版负面状态、燃烧和项目的易伤、流血、控制、自定义失明及转换后的凋零。原版失明/自定义失明、凋零/转换凋零分别去重；控制附魔的类型编号不当作效果等级。二级为每种 2 基础魔法伤害，另对每种等级至少 II 的效果增加 2，统一应用投掷时魔法系数。

玩家易伤在本项目使用 `unluck` 与 `player.Vulnerable` 表示；净化同时清除原版效果、对应分数和遗留虚弱近战修饰器。适用对象按本地图合作玩法取范围内玩家。

`alchemist/load` 在版本检查之前创建运行 objective，不调用全局玩家重置、不重置已学技能。独立玩家循环管理新增状态与礼物；死亡、转职和技能卸下时清理相应个人增益。实体附魔单独管理炸弹、毒潭、礼物，因此支持地图自定义维度，且不与通用寿命附魔争用计时。

## 验证结果（2026-09-12）

- Minecraft 26.1.2 / Java 25：73 个相关函数编译通过，两组技能等级宏参数实例化通过；新增附魔与进度通过原版 Codec 解析。
- 原版 GameTest：52 项运行断言全部通过，包含两级倍率、魔力消耗、冷却、护盾刷新、储能上限、多人拾取与丢弃物归属、治疗、净化、毒潭自动 tick、炸弹爆炸与普通瓶子落点接线。
- 最终 GameTest 日志无函数加载失败或 NBT 序列化错误；JUnit 报告保存于 `tests/alchemist-runtime-report.xml`。
- 全包 930 个函数的静态函数引用检查通过；668 个 JSON/mcmeta 基础解析通过；`git diff --check` 通过。
- 连续投掷现在只挂载本次新建的瓶子载体，避免重用同位置旧载体。通用寿命初始化改用 `set_enchantments` 移除旧附魔，避免直接写入非法 0 级附魔而破坏飞行后的回调。

## 可复现检查

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\check_alchemist.ps1 -MinecraftRoot 'D:\MC_PCL2\.minecraft'
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\test_alchemist_runtime.ps1 -MinecraftRoot 'D:\MC_PCL2\.minecraft'
```

第一个脚本使用原版命令解析器，实例化两级宏并解析新增注册项。第二个脚本使用原版 GameTest、两个具有不同 UUID/名称的模拟玩家，在全新临时世界执行生产函数；不会打开现有存档。测试夹具保留技能及必要原版/项目依赖，将无关附魔置为无效果注册占位，以隔离附魔连锁和地图机制。

GameTest 不等于完整地图联机验收。仍应在实际地图中检查左右键/F/Q 输入手感、原版投掷物碰撞、已有附魔连锁、跨维度与退出重进时的表现。测试文件位于项目已有忽略规则 `tests` 下，需要提交时注意将其纳入版本控制。
