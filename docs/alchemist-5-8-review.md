# 炼金 5–8 复检（2026-09-12）

本次以当前技能 3、4 的实现为准，不使用旧测试对它们的数值断言，也未修改生产函数。目标为本机 Minecraft Java 26.1.2。

## 发现的问题

### P1：药瓶落地回调与乘客清理回调竞争

`data/core/function/trigger/basic/arcane_pot/set_attributes.mcfunction:3` 同时给载体附加 `core:inter/pot_as_trigger` 和 `operation:stats/pas_only`。

两项附魔都在载体失去载具时触发。前者执行药瓶效果并生成技能 6 的毒潭；后者执行 `operation:stats/kill_this`，将载体向下传送 100 格并杀死。代码依赖这两个独立附魔的执行顺序；清理先发生时，正常落点的效果不能可靠完成。

原代码复检出现过落地毒潭数量断言失败，也出现过通过。仅在测试副本消除 0 级附魔后，落地断言仍失败；再移除测试副本药瓶载体上的 `pas_only` 后，38 项断言全部通过。毒潭本体的伤害、首轮脉冲、两级间隔和 120 tick 清理在各轮测试中均通过。

建议药瓶载体不使用通用 `pas_only`，由已经包含 `kill @s` 的药瓶落地函数负责落地清理，飞行超时仍由寿命机制管理。不要全局删除其他实体所需的 `pas_only`。

### P2：寿命切换写入 0 级附魔会产生实体反序列化错误

`data/operation/function/stats/timing_limited/init.mcfunction:3` 对 `minecraft:enchantments` 写入 `operation:stats/t_limited_1:0`。原版运行日志重复报告 `Value 0 outside of range [1:255]`。

`data modify` 能修改盔甲架，复跑也观察到新的寿命附魔生效；问题是等级 0 不满足组件读取范围，不能把它当成可靠的删除操作。本次没有把毒潭落地竞争归因于此错误。

建议继续使用实体 NBT 操作：先 `data remove entity` 删除旧附魔键，再 `data modify entity ... merge value` 添加等级 1 的新附魔，无需改用 `item` 指令。测试副本采用该方案后未出现上述反序列化错误。
